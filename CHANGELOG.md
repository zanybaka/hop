# Изменения

## В разработке

- 2026-11-25. Старые образы в GHCR чистятся раз в сутки: остаются 10 последних, образы production-выкаток и образ, работающий в проде.
- 2026-11-22. HOP-025. Сервер отвечает на HEAD так же, как на GET: тот же код и те же заголовки, тела нет. Это касается страницы, статических файлов и GET-методов API. HEAD к записи и к очереди relay ничего не расходует: квитанция не выдаётся, кадр остаётся в очереди. Ответы теперь несут Content-Length.
- 2026-11-22. Ответы сервера несут Permissions-Policy (камера, микрофон, геолокация и другие устройства закрыты, копирование ссылки разрешено), Cross-Origin-Opener-Policy и Cross-Origin-Resource-Policy со значением same-origin. Политика содержимого ограничивает отправку форм собственным адресом (form-action).
- 2026-11-20. HOP-010. Проба ICE на одной машине воспроизвела отказ WebKit против WebKit и показала, что оба движка прячут локальные адреса за mDNS. Автообнаружение по сетевым признакам браузера недоступно; обнаружение остаётся по приглашению, выбор границы записан кандидатом решения в TECHSPEC.
- 2026-11-20. HOP-016. На опубликованной странице передача удаляется по сроку. Откат на предыдущую ревизию и возврат сохраняют уже созданную передачу.
- 2026-11-20. Если браузеры не открывают прямой канал, пара передаёт те же зашифрованные кадры через сервер и не хранит их после доставки. Уход одной стороны сообщает второй, и та сохраняет последнюю версию по ссылке.
- 2026-11-20. Медленная загрузка не теряет резерв, пока байты продолжают приходить. Пауза без новых байтов по-прежнему освобождает резерв.
- 2026-11-20. Образ отдаёт sha сборки в /version.json. У образа есть метка service=hop, её сверяет выкладка заранее собранного образа. Список адресов закрывает staging, проверка готовности остаётся открытой.
- 2026-11-20. HOP-015. Зафиксированы бюджет короткого кода, запас диска и отказ. Каталог состояния открывается только владельцу процесса. Ответ просит браузер держаться HTTPS.
- 2026-11-20. Создание резерва и приглашения ограничено по адресу клиента и суммарно. При превышении сервер отвечает 429 и `Retry-After`. Адрес берётся из соединения. За локальным доверенным прокси это один IP в `X-Hop-Client-IP`. `X-Forwarded-For` адрес не задаёт.
- 2026-11-20. Hop размещён в корне собственного поддомена. Добавлены самостоятельный Docker-образ и сборка в GitHub Actions.
- Исправлена проверка ёмкости при загрузке максимального файла на файловых системах с дополнительными выделенными блоками.

- 2026-11-19. Публичная страница обновлена до ревизии 456f0ef с переключателем прав и плавающей панелью подключения.

- Добавлен версионированный контейнер передачи для текста и бинарных вложений с проверкой общего размера.
- Добавлен расчёт срока передачи по абсолютному дедлайну и подтверждённой активности.
- Добавлено клиентское шифрование контейнера и получение ключа из полной ссылки.
- HOP-004. Добавлены потоковое хранилище, резервы, проверка версии и удаление по сроку.
- HOP-005. Добавлен локальный API публикации, чтения и подтверждения получения.
- HOP-006. Добавлен браузерный сценарий публикации текста и файлов по полной ссылке и QR.
- HOP-008. Сравнены схемы короткого кода и записаны условия для реализации HOP-009.
- HOP-017. Добавлены одноразовые QR-приглашения, подтверждение соединения и прямой обмен для локальной проверки.
- HOP-011. После разрыва прямого обмена последняя переданная версия сохраняется по ссылке, которую оба браузера получили при подключении.
- HOP-011. Браузеры пары продолжают совместную запись через хранилище по исходной ссылке после разрыва.
- HOP-012. Добавлены управление режимом, приглашения для записи и проверка прав при фиксации загрузки.
- HOP-012. Приглашение на запись действует один раз. Владелец может запретить запись участнику. Сервер проверяет запрет и для уже начатой загрузки.
- HOP-009. Владелец может включить восьмисимвольный код для сохранённой передачи. Получатель вводит его на главной и открывает текст и файлы после отключения отправителя.
- HOP-013. Владелец может отключить участника сохранённой передачи. Старая общая ссылка и код перестают работать. Остальные участники с личным доступом продолжают обмен.
- На главной появились волны из макета, на телефоне текст и файлы переключаются вкладками. Панель подключения показывает QR и короткий код. Для совместного редактирования владелец создаёт личное приглашение.
- HOP-018. Владелец прямого соединения переключает чтение и обмен через «Доступ и защита». Получатель сохраняет свой черновик при смене прав.
- HOP-019. Окно подключения на главной показывает одноразовый код из восьми символов рядом с QR. Оба способа входа требуют подтверждения на первом устройстве.
- Поле ввода короткого кода на главной выровнено по высоте с соседними кнопками.
- HOP-020. Владелец выбирает режим получателя переключателем в редакторе. Новый QR, ссылка и короткий код открывают передачу с выбранными правами.
- HOP-021 и HOP-022. Тема и подключение поменялись местами. Действия получили иконки, а сообщения появляются рядом с действием или файлом.
- HOP-023. Панель подключения открывается поверх редактора. Кнопки копирования стоят рядом с полями ссылки и кода.
