# Зашифрованная передача

Клиент создаёт случайный 32-байтовый идентификатор и отдельный случайный 32-байтовый секрет. Полная ссылка указывает на страницу приложения и добавляет фрагмент `#v1/<id>/<secret>`. Оба значения кодируются строчным hex. Получатель читает фрагмент локально. Запросы к хранилищу используют идентификатор. Фрагмент и секрет в эти запросы не входят.

Клиент упаковывает [контейнер HOP1](container.md) и шифрует его Web Crypto AES-256-GCM. Конверт содержит ASCII `HOPG`, случайный 12-байтовый nonce, шифротекст и 16-байтовый тег. Дополнительные данные составляют UTF-8 строку `hop/HOPG/<id>`. Для каждой записи и замены клиент генерирует новый nonce. Получатель проверяет версию и тег до разбора контейнера. Ссылка даёт право прочитать содержимое. Полномочия владельца задаёт отдельный контракт.

Производитель и потребитель используют `src/envelope.mjs`. Смена несовместимого формата требует новой версии и проверки чтения старых записей. Web Crypto обрабатывает текущий контейнер целиком в памяти. Пиковый расход на iPhone и требование потокового шифрования остаются в приёмке. Для локальной проверки используется `node --test test/envelope.test.mjs`.
