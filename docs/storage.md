# Потоковое хранилище передачи

Сервер использует `openStorage(directory, options)` из `src/storage.mjs`. Он принимает шифротекст, сохраняет его в отдельном файле и держит указатель текущей версии в SQLite. Сервер резервирует место до записи. При замене он учитывает старую и новую версии одновременно. Прежний файл удаляется после успешного переключения указателя и завершения уже начатых чтений.

| Вызов | Контракт |
| --- | --- |
| `reserve({ id, version, bytes, ownerHash, hasFiles, protected, lifetime })` | Возвращает `{ token, bytes }`. Версия 0 создаёт передачу. Идентификатор и хеш отдельного ключа владельца содержат 64 строчных hex символа. Владелец задаёт срок от создания, до суток. |
| `upload(token, readable)` | Принимает Node.js Readable ровно зарезервированного размера. После фиксации возвращает `{ version, expiresAt }`. Обрыв, превышение или недостача байтов и конфликт версии оставляют предыдущую публикацию доступной. |
| `openRead(id)` | Возвращает `{ stream, size, version, expiresAt, receipt }`. Потребитель должен вычитать, передать дальше или уничтожить поток. При переполнении очереди подтверждений `receipt` равен `null`. |
| `confirm(receipt)` | После полного чтения и в пределах срока принимает одно подтверждение на текущую версию, возвращает `{ expiresAt }`. Клиент вызывает после проверки целостности. |
| `cancel(token)` | Освобождает резерв или прерывает загрузку и её очистку. Возвращает `false`, если резерв отсутствует. |
| `codeRecord(id, ownerHash?)` | Проверяет, что публикация жива, и возвращает её абсолютный срок. Если передан отпечаток владельца, сверяет право зарегистрировать короткий код. Обращение не продлевает срок. |
| `usage()` | Возвращает `{ allocated, reserved }` в байтах для файлов объектов и их резервов. |
| `close()` | Останавливает фоновую очистку, прерывает потоки и освобождает владение каталогом. |

Для создания используется `version: 0`. При замене совпадают ожидаемая версия и `ownerHash`. Резерв на создание с другим владельцем получает отказ, пока активен первый. После первого сохранения владелец, признаки защиты, момент создания и абсолютный срок зафиксированы. При замене сервер обновляет признак наличия файлов. Неактивность отсчитывается от последнего подтверждения или создания передачи. Если замена добавляет вложения по истечении этого окна, резерв получает `expired`. Сервер видит завершение своего потока. Проверку подлинности шифротекста выполняет клиент до подтверждения.

`StorageError.code` сообщает причину отказа. `missing` относится к отсутствующим записям, резервам и подтверждениям, `expired` к истёкшему сроку действующей операции, `conflict` к версии или незавершённой операции, `forbidden` к владельцу. `invalid` означает неверные метаданные, `size` неверный размер, `full` нехватку места, `interrupted` обрыв потока или закрытие хранилища. Потребитель преобразует эти причины в ошибки своего интерфейса. Внутренние ошибки файловой системы и SQLite следует возвращать без путей и подробностей.

Для одного каталога работает один серверный процесс. `capacity` по умолчанию 3 000 000 000 байт. В учёте берётся большее из округлённого размера файла и числа занятых блоков. Резервы учитываются до завершения записи, активные чтения удерживают старые файлы. Перед резервированием сервер сверяет свободное место раздела и оставляет `diskHeadroom` для прочих данных. Размер конверта ограничен 106 311 976 байтами, включая заголовки HOP1 и HOPG, максимальный манифест, 100 МБ вложений и тег. Точный размер открытых вложений проверяет клиент. Продолжительность резерва задаёт `lease`, по умолчанию 30 секунд. При запуске и затем каждые `sweepInterval` миллисекунд сервер удаляет истёкшие записи и файлы без указателя. Интервал по умолчанию 30 секунд. После перезапуска незавершённые резервы освобождаются и одноразовые подтверждения выдаются заново.

Размеры базы SQLite и журнала входят в запас раздела, а не в счётчик файлов объектов. На целевом диске следует измерить этот запас, проверить режим доступа к каталогу и замерить длительность передачи 100 МБ для выбора срока резерва. Проверки локального слоя запускаются командой `node --test test/storage.test.mjs`. Новый временный каталог, максимальный объём, борьба за квоту, обрыв замены, восстановление после незавершённой записи, срок и фоновая уборка покрыты тестами.

Перед фиксацией загрузки сервер повторно сверяет сумму фактически занятых блоков и всех действующих резервов с общей ёмкостью. Файловая система может выделить больше блоков, чем получается округлением длины файла. Такой файл сохраняется, если фактическая общая занятость помещается в лимит.
