# Автообнаружение устройств и проверка Safari

QR уже создаёт приглашение до ввода данных и требует согласия. Для автообнаружения из R4 требуется надёжно определить, что браузеры находятся в одной локальной сети. Одинаковый исходящий интернет-адрес может относиться к разным сетям и не даёт основания показать участников друг другу. Результат ICE определяет возможность связи двух уже известных участников. Сам по себе он не предоставляет список соседних браузеров. [WebRTC](https://www.w3.org/TR/webrtc/) · [RFC 8828](https://www.rfc-editor.org/rfc/rfc8828.html)

Первый подтверждённый путь для проверки автообнаружения без разрешения на публикацию данных за пределами локальной сети потребует доверенного сетевого признака. Возможные варианты для решения с владельцем: локальный доверенный сервис или область обнаружения по приглашению. Первый требует инфраструктуры и конфигурации сети, второй добавляет действие пользователя и меняет сценарий R4. Сопоставление только по интернет-адресу нарушает границу обнаружения.

## Проба ICE на одной машине, 2026-11-20

Стенд в [research/network-probe](../research/network-probe/README.md) прогнал обмен SDP через реальную сигнализацию hop между Chromium и WebKit на одном компьютере в одной сети. Результаты меняют оценку путей обнаружения.

- WebKit против WebKit не открыл канал ни в одном варианте: состояние соединения осталось новым, в статистике нет ни одного удалённого кандидата. WebKit не разрешил mDNS-имя собеседника и не собрал рефлексивный адрес даже при настроенных STUN-серверах. Симптом совпадает с настольным WebKit на публичной площадке из HOP-014.
- Chromium и WebKit соединились во всех парах, где участвовал хоть один Chromium, включая вариант без STUN.
- Оба движка прячут адреса локальных интерфейсов за mDNS на условиях прод-страницы. Chrome 155 прячет их даже на localhost; WebKit не отдал реальные адреса ни в одном варианте. Признак одной сети из локальных адресов ICE-кандидатов потребовал бы выданного доступа к камере в Chromium и недоступен в WebKit.

Следствие: путь обнаружения по локальным адресам ICE-кандидатов не работает без запроса доступа к камере и не покрывает Safari. Оставшиеся варианты прежние: приглашение уже реализовано в HOP-017 и HOP-019, локальный доверенный сервис требует установки и инфраструктуры. Кандидат решения записан в TECHSPEC как ADR-CANDIDATE; выбор остаётся за владельцем.

## Физический маршрут

На рабочей машине Chromium установил прямой канал между двумя контекстами. Отказ WebKit против WebKit воспроизведён на уровне движка; сборка Playwright отличается от настоящего Safari, поэтому приёмка на физических устройствах остаётся обязательной. Для следующей проверки нужны HTTPS-адрес, физический iPhone и второй компьютер в одной сети. Проверяем QR через штатную камеру, двусторонний обмен, разрыв и открытие той же передачи по сохранённой ссылке. Для автообнаружения отдельно проверяем гостевую сеть и случай одинакового внешнего IP у разных сетей. [WebKit о выборе ICE-кандидатов](https://webkit.org/blog/7763/a-closer-look-into-webrtc/)

HOP-010 ждёт решения владельца по границе обнаружения. Приёмка физического маршрута остаётся частью выпуска.
