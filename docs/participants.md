# Модель прав и присутствия

`createParticipants()` из `src/participants.mjs` разделяет права владельца и получателя. Интеграция передаёт в `register({ id, ownerHash, expiresAt, mode })` сохранённый хеш ключа владельца и срок передачи. `join(id, { name })` вызывается после внешней проверки права присоединиться. Он возвращает случайный токен получателя и публичный идентификатор участника. Имя ограничено 128 байтами UTF-8. Оно предназначено для отображения как текст.

При каждой записи серверу нужно вызвать `authorize(id, credential, 'write')`. В режиме `read` запись доступна владельцу. В `exchange` её могут выполнять получатели. Управление и просмотр состава участников доступны владельцу. `setMode(id, ownerHash, mode)` немедленно меняет результат следующих проверок. Владелец предъявляет отпечаток, который доверенный сервер вычисляет из отдельного ключа. Получатель предъявляет `{ token }`. Каждый путь принимает только свои полномочия. Список `presence(id, ownerHash)` содержит режим, публичные идентификаторы, имена, роли и признаки присутствия. Токены и отпечатки в список не входят.

Владелец занимает одно из восьми мест. Остальные места получают сеансы до добровольного выхода через `leave(id, token)` или истечения передачи. Состояние «нет на связи» по умолчанию наступает через минуту после последнего `heartbeat(id, credential)`. Оно не освобождает место и не меняет права. Переподключение с теми же полномочиями не занимает новое место. Выход освобождает место и завершает сеанс, а состояние криптографических ключей остаётся отдельной задачей. Присутствие не продлевает срок передачи.

Модель в памяти покрывает сценарии авторизации отдельно от долговечного слоя. Текущий HTTP использует сохранённые режим и отпечатки разрешений, а также сверяет версию передачи и срок в хранилище.

## Интеграция с сохранённой передачей

Владелец выдаёт одноразовый случайный секрет приглашения. В ссылке он находится во фрагменте `/write/<secret>`. Первый браузер предъявляет его серверу и регистрирует отпечаток своего отдельного случайного ключа. Сервер атомарно использует приглашение и выдаёт одно место. Повтор из того же клиента безопасен. Копия использованного приглашения открывает чтение. Клиент убирает приглашение из адресной строки после обработки. Пара с подтверждённым QR получает отдельное разрешение на этапе защищённого соединения.

Режим и отпечатки лежат в `exchange.sqlite`. Открытие старого каталога создаёт недостающие таблицы. Существующие записи и их схема сохраняются. Без настройки публикация работает в режиме чтения. Семь мест для получателей включают выданные и ещё не использованные приглашения. Владелец занимает восьмое место. Если участник копирует уже полученный ключ устройства из хранилища браузера, обе копии используют одну цифровую учётную запись.

Сервер проверяет права при резервировании и фиксации файла. При переходе в режим чтения или отзыве права записи незавершённая запись отклоняется. Владелец видит статус участников и вручную освобождает место отменой права записи. Такой отзыв оставляет чтение по действующей полной ссылке. Полный отзыв с обновлением ключей описан ниже. Присутствие не влияет на срок содержимого.

Проверка HTTP проходит перезапуск, предел выдачи, повтор приглашения из нового клиента, запрет изменения режима участником, смену режима и отзыв между резервом и фиксацией. В Chromium и WebKit проверены приглашение, присутствие, запись, смена режима, восстановление черновика и возврат после перезагрузки.

Владелец подтверждённой пары управляет общей настройкой через «Доступ и защита». Теми же правами пользуются прямой канал и браузеры, открывшие ссылку продолжения. [Проверка записи в прямом канале](pairing.md#права-после-подключения).

## Режим для общего приглашения

Владелец выбирает «Только чтение» или «Обмен» переключателем в редакторе. Ссылка из панели подключения, её QR и новый короткий код выдают ключ браузера участника. В режиме чтения это место позволяет оставаться на связи, а сервер отклоняет отправку. Когда владелец включает обмен, уже подключённые участники получают право отправлять. Владелец управляет передачей своим отдельным ключом.

При входе по старой полной ссылке или старому короткому коду свежий браузер читает данные. Действующие персональные полномочия сохраняются. Старое личное приглашение остаётся одноразовым. По кнопке «Участники» владелец видит зарегистрированные устройства и может отключить получателя.

## Отзыв чтения

Для отзыва владелец нажимает «Отключить» рядом с участником и подтверждает смену общей ссылки. Сервер одновременно отзывает личное разрешение и старый адрес, фиксирует последнюю версию под новым ключом, оставляет персональный доступ остальным участникам с зарегистрированными браузерами. Старый короткий код также перестаёт работать. Новый можно выпустить в окне ссылки. Отключённый браузер позволяет скопировать локальный текст и скачать локальные файлы из уже открытой вкладки. Полное обновление страницы требует действующего доступа.

Клиент хранит закрытый ключ восстановления вместе с полномочиями в хранилище браузера. Для нового участника открытый ключ фиксируется в момент использования приглашения. Прежний участник без ключа должен один раз открыть передачу перед отключением другого участника. Сервер отклоняет частичную смену. Совместимость API и правила отката описаны в [контракте публикации](publication-api.md).
