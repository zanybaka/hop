# 002. Прямой канал открывается после подтверждения приглашения

Дата: 2026-11-14. Решение действует для локальной реализации QR-пары.

## Контекст

Два браузера должны начать обмен только после согласия создателя. При доступном прямом маршруте содержимое передаётся между браузерами. Хранилище не должно получать ключ этого обмена. Связь между различными сетями и автоматическое обнаружение имеют собственные требования.

## Решение

Применяем одноразовое приглашение, защищённую сигнализацию и WebRTC DataChannel. QR содержит секрет приглашения во фрагменте. Отдельные полномочия 256 бит ограничивают чтение сигналов и одобрение. Сервер хранит временные записи, а браузер защищает описание сессии AES-GCM с отдельным ключом из HKDF. Полезная нагрузка использует HOPG и отправляется напрямую. Для локальной проверки внешние STUN и TURN не настроены.

Обмен через сервер даёт более предсказуемый сетевой маршрут и связан с дополнительным трафиком и хранением. Открытие прямого канала без подтверждения оставило бы создателя без возможности отклонить запрос. После разрыва клиент с последней переданной версией может сохранить отдельную шифрованную публикацию.

## Реализация и проверка

`src/pairing.mjs` задаёт жизненный цикл, `src/pairing-client.mjs` защищает сигнализацию, `src/local-channel.mjs` задаёт транспорт. `web/pair.mjs` реализует действия пользователей. [Контракт и ограничения](../docs/pairing.md).

HOP-019 добавляет ручной вход с восьмисимвольным кодом. Браузер применяет механизм слепой подписи из [ADR 004](004-single-server-short-code.md) к тому же одноразовому приглашению. Зашифрованная запись существует только в памяти сервера и исчезает при первом запросе, отмене или истечении приглашения. Для получения секрета по короткому коду действуют ограничения выдачи и модель угроз ADR 004. Для установления связи по-прежнему нужно согласие владельца.

- [x] Нельзя присоединиться по уже использованному приглашению или одобрить запрос от имени получателя.
- [x] В Chromium два свежих контекста передают содержимое в обе стороны. Локальный черновик при конфликте сохраняется.
- [x] После разрыва успешно переданная версия открывается по полной ссылке.
- [ ] Прямое соединение в Safari и автопоиск устройств требуют отдельной приёмки.
