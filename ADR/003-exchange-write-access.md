# 003. Проверять запись по роли и текущему режиму

Дата: 2026-11-14. Действует для локальной реализации публикации и продолжения QR-сеанса.

Обычная полная ссылка позволяет читать шифрованную публикацию. Ключ владельца и ключи участников дают серверу отдельное основание разрешить запись. Владелец создаёт одноразовое приглашение, которое первый открывший браузер обменивает на собственный ключ. У подтверждённой QR-пары отдельный ключ получателя выводится из защищённого обмена. Право управления остаётся у создателя. Ключ чтения и содержание остаются на устройстве.

Хранилище сверяет версию, режим и отпечаток ключа при выдаче резерва и перед фиксацией. Только проверка перед резервом позволила бы завершить загрузку после смены режима. Выдача ключа владельца всем участникам лишила бы владельца самостоятельного управления. Режим и отпечатки хранятся в дополнительном файле SQLite под той же блокировкой процесса, что и основное хранилище. Подключение существующего каталога не меняет таблицу записей.

Экран доступа позволяет владельцу запретить запись отдельному участнику. Действующая ссылка по-прежнему даёт чтение, пока владелец не сменит ключ и приглашение по будущему протоколу. Протокол короткого кода этим решением не утверждается.

- [x] HTTP отклоняет запись без разрешения, повтор приглашения из другого клиента и попытку участника изменить режим.
- [x] Режим и разрешение сохраняются после перезапуска. Семь разрешений и владелец исчерпывают лимит.
- [x] Переключение на чтение и отзыв записи отклоняют фиксацию ранее зарезервированной загрузки.
- [x] Chromium и WebKit проходят смену режима, восстановление черновика и возврат после перезагрузки.
- [x] Chromium продолжает общий обмен по прежней ссылке после разрыва прямого канала.

Код: `src/storage.mjs`, `src/exchange-access.mjs`, `src/publication.mjs`, `web/app.mjs`. [Контракт доступа](../docs/participants.md).
